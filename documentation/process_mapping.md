# Vendor Payment Process Mapping

## 1. Purpose

Document the existing vendor invoice processing workflow (AS-IS) and the proposed optimized workflow (TO-BE).

## 2. AS-IS Process

| Stage                      | Processing Time |
| -------------------------- | --------------: |
| Invoice Registration       |          2 days |
| Invoice Verification       |          4 days |
| Exception Resolution       |          3 days |
| Manager Approval           |          5 days |
| Payment Preparation        |          2 days |
| Payment-Ready Confirmation |          2 days |
| Total                      |         18 days |

### Identified Bottlenecks

- Manual invoice registration
- Delayed verification
- Repeated invoice corrections
- Slow managerial approvals
- Lack of centralized tracking

## 3. TO-BE Process

| Stage                      | Target Processing Time |
| -------------------------- | ---------------------: |
| Invoice Registration       |               0.5 days |
| Invoice Verification       |               1.5 days |
| Exception Resolution       |                  1 day |
| Manager Approval           |               1.5 days |
| Payment Preparation        |                  1 day |
| Payment-Ready Confirmation |               0.5 days |
| Total                      |                 6 days |

### Proposed Improvements

- Centralized invoice submission
- Standardized invoice verification checklist
- Structured exception management
- Defined approval matrix
- Automated reminders
- Centralized payment tracking
- Regular payment-ready reviews

## 4. Performance Comparison

| Metric           |   AS-IS |  TO-BE |
| ---------------- | ------: | -----: |
| Processing Time  | 18 days | 6 days |
| Target Reduction |       - |  66.7% |

## 5. Key Assumptions

- All processing times are illustrative.
- Time is measured in calendar days.
- Stage durations represent sequential elapsed processing time.
- The six-day target ends when an invoice becomes approved and payment-ready.
- Actual payment release is monitored separately against contractual due dates.
- Exceptions are assumed to be resolved within the allocated stage time.

## 6. Expected Outcome

The redesigned workflow aims to reduce internal invoice processing time from 18 calendar days to 6 calendar days through standardized procedures, improved accountability and better process visibility.

Actual performance improvements must be validated using operational data.
